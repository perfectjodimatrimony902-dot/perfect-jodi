PERFECT JODI MATRIMONY - REAL-TIME SOCKET.IO CHAT SYSTEM SUMMARY

Updated: 26 November 2026
Project: Perfect Jodi (Next.js + Node.js + Express + Socket.IO + MongoDB Atlas)

--------------------------------------------------------------------------------
1. WHAT WE BUILT (OVERVIEW)
--------------------------------------------------------------------------------
A complete, production-ready, real-time 1-on-1 chat and notification system:
- Instant message delivery (0 milliseconds delay) without refreshing the page.
- Static & LocalStorage persistence:
    * Chat messages are stored in client browser LocalStorage (pj_local_chat_...).
    * ZERO database space is consumed for storing chat history.
    * Database persistence logic is preserved and toggleable via STORE_CHATS_IN_DB.
- Message status indicators:
    * Sent (Single tick: ✓)
    * Delivered (Double tick: ✓✓) - Delivered to recipient's screen.
    * Read (Double gold tick: ✓✓) - Recipient opened and viewed the chat.
- Typing indicators ("Priya is typing...") that auto-clear after stopping.
- Real-time online/offline presence tracking with "Last seen" timestamps.
- Audio notification chime (Web Audio API) when messages arrive.
- Visual popup alert banners (Sonner) for both sent and received messages.
- Global notification listener so users get alerts anywhere on the website.
- Dual delivery mode: WebSocket (real-time) with automatic REST fallback
  so chat works 100% reliably even if connections fluctuate.

--------------------------------------------------------------------------------
2. DATABASE STORAGE OPTIMIZATION (STATIC & LOCALSTORAGE PERSISTENCE)
--------------------------------------------------------------------------------
To protect MongoDB Atlas storage quota and avoid database bloat:
1. Messages are persisted on the client using browser LocalStorage.
   Each conversation keeps its own history (`pj_local_chat_${conversationId}`).
2. Chat messages survive page refreshes, tab closures, and device restarts.
3. In `src/server/socket.js` and `src/app/api/messages/[id]/route.ts`:
   - Added `STORE_CHATS_IN_DB = process.env.STORE_CHATS_IN_DB === "true"`.
   - Default is FALSE: Messages are transmitted purely in real-time over Socket.IO
     without writing documents to the MongoDB `Message` collection.
   - The complete MongoDB persistence logic remains 100% intact! Whenever you want
     to store chats in MongoDB Atlas in the future, simply set:
         STORE_CHATS_IN_DB=true
     in `.env.local`. No code changes required!

--------------------------------------------------------------------------------
3. REAL-TIME DELIVERY RESOLUTION (NO REFRESH NEEDED)
--------------------------------------------------------------------------------
We resolved the root causes that previously required page refreshing:
1. Fixed CORS Configuration in `server.js` and `socket-server.js`:
   Changed `origin: "*"` with `credentials: true` to a dynamic origin resolver.
   Browser WebSocket connections now successfully establish authenticated sessions.
2. Token Availability via `/api/auth/me`:
   `/api/auth/me` now supplies the active JWT token in the JSON payload, allowing
   browser JavaScript to store it in `localStorage` and pass it directly to Socket.IO.
3. Resilient In-Memory Delivery:
   `src/server/socket.js` no longer blocks message transmission on MongoDB queries.
   Messages are broadcasted over Socket.IO in < 5ms directly to the recipient's room
   and active conversation room.
4. Auto-Rendering on Incoming Messages:
   The client listener immediately appends incoming messages into active React state
   and `localStorage`, causing instant UI re-renders without refreshing.

--------------------------------------------------------------------------------
4. KEY FILES CREATED & MODIFIED
--------------------------------------------------------------------------------

A. BACKEND & SERVERS:
   1. server.js
      - Integrated server running both Next.js and Socket.IO on port 8080.
      - Dynamic CORS origin for credentialed WebSockets.
      - Started automatically via `npm run dev`.

   2. src/server/socket.js
      - The core Socket.IO engine.
      - Authenticates every socket connection using JWT (JSON Web Token).
      - Multi-tab tracking: keeps users online across multiple browser tabs.
      - In-memory conversation cache (10 min TTL) to avoid redundant MongoDB reads.
      - Zero-db-growth mode: broadcasts messages in real-time without bloating MongoDB.
      - Preserved database logic (toggleable via STORE_CHATS_IN_DB=true).
      - Emits events: receive-message, message-delivered, message-read,
        user-online, user-offline, user-typing, user-stop-typing.

   3. socket-server.js
      - Standalone Socket.IO server option on port 5001.

B. MONGODB DATABASE MODELS:
   4. src/models/Conversation.ts
      - Stores participants [UserA, UserB].
      - Ensures only one unique conversation exists per pair of users.

   5. src/models/Message.ts
      - Message schema fully preserved with indexes and status tracking.

   6. src/models/User.ts
      - Tracks `isOnline` (Boolean) and `lastSeen` (Date) for live presence.

C. BACKEND REST APIS:
   7. src/app/api/conversations/route.ts
      - GET: Fetches the logged-in user's chat list with unread counts and photos.
      - POST: Creates or opens a chat (supports User ID or Profile ID).

   8. src/app/api/messages/[id]/route.ts
      - GET: Loads chat recipient details and any stored messages.
      - POST: High-reliability fallback to send messages if socket reconnects.

   9. src/app/api/messages/[id]/read-all/route.ts
      - PATCH: Marks all unread messages in a conversation as read.

   10. src/app/api/auth/me/route.ts
       - Returns user session, profile, and active token for Socket.IO authentication.

D. FRONTEND CHAT UI & SERVICES:
   11. src/lib/socket-client.ts
       - Singleton Socket.IO client with credentials and auto-reconnect.

   12. src/app/(member)/messages/page.tsx
       - Beautiful, responsive matrimony chat layout.
       - Instant 0ms LocalStorage static persistence.
       - Audio sound effect on incoming messages.
       - Alert popup toast when a message is sent or received.

   13. src/components/site/SocketNotificationListener.tsx
       - Global background listener mounted in app layout.

   14. package.json
       - Configured `"dev": "node --max-old-space-size=2048 server.js"`.
